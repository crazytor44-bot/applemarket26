# Публикации в Telegram с первого согласования

Для запланированного поста создаём **один файл только после того, как владелец утвердил и текст, и конкретное изображение**: `telegram_channel/post_queue/YYYY-MM-DD-slug.json`.

Пример структуры (не создаёт публикацию):

```json
{
  "approved": true,
  "channel": "@applemarket26",
  "publish_at": "2026-10-20T09:00:00+03:00",
  "text": "Точный текст, утверждённый владельцем",
  "parse_mode": "plain",
  "pin": false,
  "photo_repository_path": "telegram_channel/media/approved-poster.jpg",
  "photo_git_blob_sha": "SHA1 Git blob оригинального утверждённого фото"
}
```

Фото кладём в `telegram_channel/media/`. Без фото, подтверждённого SHA, отметки `approved=true` или нужного времени **ничего не отправляем**.

При создании JSON проверка стартует сразу, но отправка произойдёт **не раньше `publish_at`**. Отдельный workflow раз в ~10 минут в дневное время Москвы (08:00–20:59) подхватывает готовые посты. GitHub Actions может задержать cron, **точность до минуты не гарантируется**. Можно запустить workflow вручную (Run workflow), он опубликует только уже наступившие утверждённые посты.

Чтобы не было повторов, перед `sendPhoto` создаётся атомарная запись `telegram_channel/post_receipts/<имя>.json`. Если запись уже существует, второй раз не отправляем. После успешной отправки туда добавляется прямая ссылка. Если связь с Telegram оборвалась и неизвестно, дошло ли видео/фото, **автоматических повторов нет**: нужен контроль канала и лога. Синхронизацию цен не меняем.

Локальная безопасная проверка: `python3 telegram_channel/post_queue.py --check`.
