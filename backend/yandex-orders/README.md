# А Маркет — безопасный приём заявок (подготовка)

Код готов к развёртыванию на Yandex Cloud в России. Пока платёжный аккаунт не активен, **API не развёрнут, новые заказы остаются через WhatsApp**. В GitHub нет токенов, персональных данных и платёжных реквизитов.

## Перед включением
1. Завершить регистрацию платёжного аккаунта Яндекс Cloud. **Не создавать платные ресурсы без согласия владельца.** Проверить актуальные тарифы.
2. Выбрать каталог в `ru-central1`, завести базу **YDB Serverless** (регион Россия).
3. В редакторе YDB выполнить `schema.sql`. В YDB настроить ограниченный доступ для сервисного аккаунта функции, не публиковать БД.
4. Создать Cloud Function (Python 3.12 или поддерживаемая актуальная версия) с файлами `index.py`, `requirements.txt`, entry point `index.handler`.
5. Привязать сервисный аккаунт с необходимыми правами доступа к **этой** БД. Переменные окружения функции:
   - `YDB_ENDPOINT`: endpoint из консоли без `/?database=` (пример `grpcs://ydb.serverless.yandexcloud.net:2135`);
   - `YDB_DATABASE`: путь базы вида `/ru-central1/...`;
   - `TELEGRAM_BOT_TOKEN`: токен отдельного бота (секрет — не коммитить);
   - `TELEGRAM_CHAT_ID`: ID чата с владельцем (не коммитить).
   - `ADMIN_ACCESS_TOKEN`: секретный случайный ключ длиной 32+ символа для просмотра заявок (не коммитить). Генерируйте криптографически случайным способом, например `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
   Использовать защищённые секреты/механизм конфигурации Яндекс Cloud; ограничить доступ по IAM.
6. Протестировать вход в `/orders-admin/` с ключом администратора: запрос GET к функции должен возвращать последние 100 заказов только с заголовком `Authorization: Bearer <key>`. Никогда не вставлять ключ в страницу, ссылку или адресную строку и не сохранять его в браузере. Вход по ключу — временный технический вариант; для длительной эксплуатации лучше внедрить персональную авторизацию с MFA, журналированием и ограничением попыток.
7. После проверки вручную выдать функции доступ для HTTPS вызовов, протестировать OPTIONS, POST, запись в БД и уведомление Telegram. **В продакшене подключить защиту от спама (SmartCaptcha, лимиты вызовов), мониторинг расходов и ошибок.** Белый список Origin не является полноценной защитой от ботов.
8. В `assets/orders-config.json` указать HTTPS URL функции в поле `apiUrl`; только после теста заявки с контрольным номером на тестовом телефоне. Файл публичный, **URL можно публиковать, секреты нельзя**.
9. Предварительно опубликовать политику обработки персональных данных, оформить необходимые уведомления Роскомнадзора, при необходимости согласие на трансграничную передачу. Не складывать в Telegram имя, телефон или другие ПДн.

## Принцип работы
Браузер передаёт только нужные данные заказа по HTTPS в функцию. Функция валидирует запрос, сохраняет в YDB, присваивает номер и отдаёт подтверждение. Уведомление Telegram содержит лишь номер и сумму заказа — без данных клиента.

**Цена не является окончательным предложением:** клиентская сторона сверяет цену с каталогом, но итог должен подтвердить менеджер. Нельзя доверять цене, пришедшей из браузера, для автоматического выставления счёта.

**Возможные дальнейшие улучшения**: вход с MFA вместо ключа доступа, выгрузка данных, сроки хранения и удаления, антиспам и аудит доступа. Нельзя выдавать доступ к базе данных из кода на публичном сайте.

Справка: https://yandex.cloud/ru/docs/ydb/tutorials/connect-from-cf и https://yandex.cloud/ru/docs/functions/concepts/function-invoke.
